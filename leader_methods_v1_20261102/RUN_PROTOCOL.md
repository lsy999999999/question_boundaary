# 提示词的装配与执行

本目录交付一个可装配的提示词方案与方法库。本轮没有启动新模型调查，也没有实现自动编排、日期过滤、安全隔离或实验执行服务。

## 角色和信息边界

组织者持有原论文、隐藏结果、评估规则和测量来源，负责返回日期合格文献与允许的数据。leader 和研究 agent 都使用全新上下文及 gpt-6-luna；两者都不接触答案。leader 得到 LEADER_SYSTEM_PROMPT.md，研究 agent 得到 RESEARCHER_SYSTEM_PROMPT.md。也可以用同一模型顺序承担这两个阶段；本方案没有新增固定人数要求。

leader 先得到方法索引，不默认装入44张完整卡片。按 ID 或标签每轮取1–3张卡；单轮最多取6张。新方法可以记入运行内提案，方法库不限制候选解释的范围。

文件名“系统提示词”指可装入模型上下文的内容；文件本身不能执行工具隔离、时间过滤和工具调用。组织者需要通过实际运行接口落实这些约束。

## 组织者开场消息模板

```text
CASE_ID: <匿名案例编号>
CASE_BRIEF: <实验构造、现象和研究问题，不含作者机制>
BACKGROUND_CUTOFF: <最早公开时间之前，含时区/日期粒度>
OBSERVATIONS: <已开放测量 ID、定义、单位、独立重复单位、误差与缺失>
SOURCE_CARDS: <当前可用、日期合格的背景知识；可为空>
MODEL_CARDS: []
ACTION_HISTORY: []
METHOD_INDEX: <METHOD_INDEX.md 的内容>
CAPABILITIES:
  literature: <检索代理可用的查询和日期过滤接口>
  compute: <实际可用的代数、拟合、模拟和数据读取接口>
  measured_evidence: <允许请求的测量种类，不含答案或预期方向>
  physical_experiment: <真实可用的设备；没有就填 unavailable>
  direct_access: <实际文件/网络权限，说明哪些是协议限制>
BUDGET:
  leader_turns: <整数>
  researcher_turns: <整数>
  literature_requests: <整数>
  compute_requests: <整数>
  evidence_releases: <整数>
  wall_clock_and_spend_cap: <真实上限>
STOP_RULES: <预算用尽、关键资源不可得、完成封存预测等>
请先识别主要缺口，申请相关方法卡，然后安排第一项具体任务。
```

所有预算必须在调用前填好。建议初次开发可用6轮负责人决策、6轮执行回复、6次检索、10次计算和4次证据开放；这是新方案的开发预算建议，尚未冻结或执行，也不与旧四轮结果作等预算比较。每次计算/数据开放都记账，组合请求不能绕过上限。

## 方法卡调用

```sh
python3 method_cards.py --list
python3 method_cards.py --ids M13 M15 M23
python3 method_cards.py --tag unclosed_model --limit 3
```

该工具仅按显式 ID/标签取卡，不调用模型、不自行诊断、不执行实验。看完整方法库使用 METHOD_LIBRARY.md；可供程序读取的版本是 METHOD_LIBRARY.json。

## 中间产物

知识卡：来源、实际版本日期、对象、输入/输出变量、单位、成立条件、可借用的关系和迁移风险。

模型卡：模型 ID、结构版本、目标量、状态变量、输入、观测映射、方程、参数、初值/边界、知识来源、新增假设、拟合数据、已执行检查、支持/反例、尚缺证据。

行动卡：行动前模型集合、请求内容、预算、各模型的不同预测/可验收产物、实际返回、状态更新。拟合、评测和失败记录独立保留；测量开放后不得改写事前承诺。

## 本项目已有案例如何使用

RNA案例的上一轮记录保持冻结。此次方法库由已审读结果的组织者整理，同一案例重跑属于开发改进；原先已公开的保留数据现在也属于开发数据。即使给新上下文的agent运行，也不能把组织者已据此修改流程后的成功说成全新盲确认。

方法卡不写RNA答案、不指定它该申请哪一种特定测量、不含目标论文的自由能、参数或推导链。后续要检验能否迁移，应使用未参与本次整理的新案例/新保留数据，另建运行目录。当前用户要求先建立提示词方法库，本轮不额外启动验证实验。
