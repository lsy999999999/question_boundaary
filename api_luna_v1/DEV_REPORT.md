# Luna 替换实验：开发结果

本轮已通过原 V4 开发门槛：28 个任务/方法结果，80 次真实 API 生成，无效输出 0，预测顺序/哈希/提交后评测错误均为 0。两个数值基线的 8 个结果与原 V4 在 1e-12 绝对误差内一致，动作及表征序列一致。正式评测另存，开发数据不充当正式结果。

| 方法 | Qwen 中位 NMSE | Luna 中位 NMSE | Qwen 无效/16 | Luna 无效/16 |
|---|---:|---:|---:|---:|
| 无卡片 plain | 0.000834 | 0.000368 | 0 | 0 |
| 正确卡片 retrieval | 0.000675 | 0.000368 | 0 | 0 |
| 正确卡片+映射 structured | 0.001713 | 0.000368 | 3 | 0 |
| 错配卡片+映射 shuffled | 0.000551 | 0.000368 | 0 | 0 |
| 固定实验 no_active | 0.001127 | 0.000279 | 2 | 0 |

强数值基线 history_cv 中位 NMSE 为 0.000403。每个 agent 方法只有 4 个开发任务；所有方法的 Luna 对 Qwen 比较均为 3 胜，no_active 另有 1 个在 1e-12 容差内平局，其余方法另有 1 负。

Luna 80/80 次选择提示中当前交叉验证误差最小的候选，Qwen 为 32/80（其中 5 次决策有格式错误，全部保留）。这说明当前改善可以通过更稳定地使用候选验证表来解释，尚无须诉诸新表征的创造。

structured 与 shuffled 的四个开发任务最终表征、动作序列和得分全部相同。卡片正文仍影响部分引用：structured 有 7/16 次有效非空引用，shuffled 为 3/16。逐条审读 32 次映射，structured 的 7 次非空引用与所供正文相符；shuffled 的 3 次中，1 次相符、2 次不符，另外分别有 9/13 次 none。此为单人非盲语义审读，不是目标机制真伪判定。

例如 shuffled 的 storage 卡片实际描述传输时延，模型却在 memory 任务两次用它解释累积历史；相反，另一次 transport 引用的曲率关系符合该编号下实际放置的饱和正文。不能把模型概括为一概忽略正文或一概正确映射。

structured 在 memory 任务最后从 memory_slow 改为 memory_fast，shuffled 作出同样修订。修订对应当前工具验证误差排序变化；此前三次预测 MSE 约为 0.000134、0.000179、0.000165。模型提出的“匹配当前状态和输入后改变历史”条件，尚未由专门的匹配状态实验直接检验。最终独立预测 NMSE 为 0.000618，修订次数本身不表示预测改善。

开发共 248,939 输入 token、17,402 生成 token，其中 8,410 被服务标记为推理 token；80 次 finish_reason 均为 stop。请求与返回名均为 gpt-6-luna；服务实际权重和价格未独立核验。API 的 512-token 上限与 Qwen 的可见新 token 上限不能当作相同计算量。

明细见 CROSS_MODEL_dev.json、SEMANTIC_REVIEW_DEV.json 和 runs/dev/。
