# 从解释冲突到新状态变量：可执行原型 V2

2026-10-31。用户要求直接实现，不开展单 agent / 多 agent 消融，所有实验模型调用使用 gpt-6-luna。旧版数据不变。本轮是一条探索性运行轨迹，不是新颖性或性能优越性的证明。

## 实现重点

原系统把 11 个完整表征交给模型选择。本版只提供一个当前状态线性模型作为起点，以及受限的数学表达语言。Luna 自行写出观测状态的导数项、最多两个递归潜在状态及其演化关系，工具只拟合其提出的式子，不再穷举预写表征。

1. 从公开轨迹找出当前输入、可见状态相近而局部变化率不同的观测对，作为“解释冲突”线索。近似匹配和有噪声导数不构成隐藏变量存在的证明。
2. 按当前冲突建立最多两个独立研究分支，使用相同 Luna 模型、独立上下文。每个分支给出目标冲突、父假说、可执行关系、潜在变量的含义、跨领域类比及其失败条件。类比来自模型知识，未进行文献检索，不伪造出处。
3. 数值工具只拟合已提交假说，并返回整条轨迹留出的预测诊断。保留初始解释和所有已生成解释作为竞争者。
4. Luna 根据竞争解释设计两条自定义分段输入，明确要区分什么。所有竞争解释先提交定量预测，随后工具才执行两条输入。近似相同状态是否实现、误差是否分离均如实记录，不把“想做的反证”写成已经完成。
5. 下一轮只根据已观测证据修订或新建假说，形成带来源、父节点、冲突和前瞻预测误差的理论图谱。三轮后提交最终模型，再查看六条封存输入的预测表现。

## 为什么不是固定三个角色

研究组织单位是“尚未解释的冲突及其竞争解释”，分支有父节点、目标证据和存续记录。实验设计是共享的 Luna 调用，用于产生区分分支的干预；没有把多个提示词角色称为创新。原型最多两个并列分支，后续是否需要更多由实际未解问题决定。

## 范围与预算

- 一个合成动态系统，三条初始观测，三轮、每轮两条新输入，最终六条封存输入；观察的是一次重新发现尝试。
- 每轮最多两个提出假说调用、一个实验设计调用；最后一个总结调用。有效科学调用预计 10 次，另允许每次输出一次格式/表达式修复，所有修复留痕，总调用硬上限 20。
- 所有调用请求及返回名均须为 gpt-6-luna，temperature=0，max_completion_tokens=2048，总生成上限 40,960 token。不自动重试网络错误，不切换模型。
- 实验由第二台服务器 CPU 执行，语言生成走用户已授权接口；不加载本地 Qwen，不使用服务器显卡。
- 此版本独立预算/任务/表达式语言，不与旧版分数直接比较。无需人数对照，仍保留执行正确性检查和预测后观察的顺序记录。
- 潜在状态初值固定为零、总状态数/运算符/参数边界有约束；“开放”仅相对于旧版固定表征表，不是无限制数学创造。

## 新颖性的边界

潜在状态建模、符号回归、主动实验、反例驱动修订都不是新概念。本轮具体尝试把“同一旧描述对应不同变化的冲突证据”作为新增概念的入口，并保留概念产生、解释失败与干预预测的可追踪链。是否区别于预测状态表示、系统辨识、反例引导合成和现有科学发现系统，需要后续最近工作对照；本轮不声称已经获得论文级 novelty。

## 交付

代码、冻结配置、全部 Luna 原文和调用账本、生成假说及拟合参数、冲突证据、预测/观测、理论图谱、执行审计及中文运行报告。报告区分实现能力、实际触发的行为和未完成能力。

## V1 接入失败后的独立版本

V1 的两次真实调用分别输出非法 JSON、来源字段层级错误，尚未执行新增干预。V2 增加 response_format=json_object，并把 provenance 放在顶层以简化 schema。科学任务、拟合、干预及预算保持原样，从头运行，不把 V1 回答当作 V2 假说或结果。V1 原始回答和成本保留。
